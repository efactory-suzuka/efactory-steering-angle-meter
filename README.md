## Formal flow

BOOT → PERMISSION → SENSOR_CHECK → MOUNT_GUIDE → CENTER_WAIT → CENTER_CAPTURE → AXIS_CALIBRATION → MEASURING → RESULT.
Only an explicit, unmoved Finish button activation (or keyboard Enter/Space) enters RESULT. Pointer/touch releases alone never finish. Drag, scroll, cancellation and viewport changes disarm the following compatibility click. Confirming a MAX does not finish measurement. PAUSED, SENSOR_ERROR and REFERENCE_LOST invalidate existing maxima and require a new reference.
Mount the device securely on the handlebar in any readable rigid orientation: portrait, landscape, reversed or arbitrarily tilted. Its attachment must not move during measurement. The SVG shows a rotated device secured to a handlebar; there is no forward-facing mounting requirement. Left/right inversion defaults to false and is not needed merely because mounting orientation changes.
CENTER captures a stable 700 ms cluster, not the button's instantaneous reading, and stores mean zeroQuaternion, raw zeroGravityUnit and polarity-resolved upZero. Motion, excessive full quaternion span, gravity magnitude variation and sample gaps reset stillness. Deprecated forwardZero/rightZero fields remain only as a generic orthonormal diagnostic basis for compatibility; they have no vehicle-direction meaning and do not influence steering.

## Provisional settings and estimation

src/config/measurement.ts contains AxisCalibrationMode (RAW_GYRO / TRANSFORMED_GYRO), invertLeftRight and gravityUpSign. Default TRANSFORMED_GYRO follows the earlier synthetic reference design; it has not been shown superior on iPhone or Android. Raw gravity polarity remains unchanged in diagnostics. gravityUpSign now defaults to AUTO: stationary CENTER compares raw acceleration with inverse(zeroQuaternion) applied to earth up, records the resolved sign and alignment, and rejects absolute dot product below 0.8. Explicit +1/-1 adapter overrides remain available. This uses observable vertical, not compass yaw. Raw gravity used by quality checks is unchanged.
Formal calibration uses time-weighted non-centered PCA, the same pca3 primitive as Phase 5, anchored at captured CENTER. Acceptance uses configured sample count, duration, total rotation, PCA ratio and outlier angle. PCA axis sign is fixed by gravity: negate the normalized axis if dot(axis,upZero) < 0. Only abs(dot(axis,upZero)) < AXIS_MIN_UP_DOT (provisional 0.01) is sign ambiguous; the calibration summary explicitly reports axisUpAlignment and axisSignAmbiguous. Vertical caster=0 gives dot=1, the clearest case. Phase 5 A/B diagnostics continue independently with their own diagnostic anchor.
qRel = inverse(qZero) * qNow. Swing/twist decomposition supplies signedTwistDeg about the gravity-signed PCA axis. Hamilton active positive twist is LEFT (counterclockwise viewed from above), so output = -signedTwistDeg, then the explicit inversion setting if selected. LEFT is negative, RIGHT positive, with the configured CENTER deadband. No physical-top projection, sideScore or forward/right estimate is used; user instructions never determine direction.
Gyro is transformed into Z0 and projected onto the steering axis. A complementary filter integrates previously received velocity on real performance-clock intervals and corrects only on new relative orientation samples (tau 250 ms). Abnormal dt does not integrate. DeviceOrientation and DeviceMotion never need to arrive together; browser event timestamps remain separate diagnostics.
Only displayAngleDeg uses the 80 ms gauge smoothing. liveAngleDeg feeds MAX tracking. The SVG range expands from ±60 to ±75 after 58°, and to ±90 after 73°, and does not shrink during a measurement.

## Confirmed maxima and quality

The MAX tracker requires continuous 700 ms stillness, gyro ≤1.5 dps and live angle span ≤0.35°. It uses the median of samples in the latest 700 ms; a bracketing sample proves duration and continuity. Minimum lock angle is 3°, update hysteresis 0.20°. Production passes explicit coreQuality: GOOD only when axis/swing/gravity are all GOOD, CHECK when any is CHECK, RETRY when any is BAD. Only core GOOD may certify a MAX. Core CHECK immediately clears the candidate window and hold progress; recovery requires a new full 700 ms. Confirmed maxima are retained and live/display angles and direction continue. Absolute-only CHECK, MAGNETIC and unavailable absolute reference are nonblocking. At 30° confirmed then 32° moving, the needle moves while the marker stays at 30° until stillness qualifies again.
Production uses VehicleValidationController and GuidanceViewModel('CORE'). Secondary instability warnings depend only on core CHECK; absolute-only CHECK cannot change the primary instruction or display that warning. The historical MeasurementController, full-quality MaxAngleTracker input and default aggregate GuidanceViewModel branch preserve the previous v0.3.3 API so its contradictory absolute-CHECK regression tests remain unchanged. They are compatibility branches; the app explicitly uses the new core-only path, covered separately by new tests. aggregate quality remains available in debug.
LEFT is negative. Lock-to-Lock = confirmedRightMaxDeg − confirmedLeftMaxDeg. Incomplete or invalid maxima display no numeric Lock-to-Lock.
Normal Quality shows GOOD/CHECK/RETRY/MAGNETIC; axis/swing/gravity/absolute are diagnostic only. Axis uses a recent gyro PCA; swing and predicted gravity residual use the captured reference. Dynamic acceleration defers gravity evaluation. BAD requires configured hold times; two or more core BAD channels persisting 500 ms trigger REFERENCE_LOST and invalidate maxima. Time gaps cannot count toward fault duration.
Absolute orientation / compass supplies auxiliary quality only. Magnetic anomalies do not stop measurement or feed steering angle; unavailable absolute data allows normal relative measurement. Absolute fallback is preserved diagnostically and is not adopted as the formal relative source.

## Unverified limits

Real iPhone/Android permissions, rates, gyro axis/polarity, gravity polarity, relative source availability, holder mounting, compass behavior, clipboard/save and actual vehicle repeatability/accuracy require physical validation. GOOD describes configured consistency checks, not certified measurement accuracy. Same-axis vehicle motion or holder slip may be unobservable from relative pose alone. Thresholds remain experimental. This is not a certified instrument for regulatory conformity, service quality, safety or manufacturer dimensions. No Phase 7 implementation.

## Experimental Rear Stand Compensation

Available only through ?debug=1; default OFF, no persisted opt-in. A quaternion-anchored two-angle fit separates steering from assumed body yaw in CENTER Z0. It never replaces normal live angle, LEFT/RIGHT MAX or Lock-to-Lock. OFF and ON regression tests compare those formal fields exactly with the v0.3.3 calculation for core-good streams. The intentional core-only MAX policy change applies in both modes.
The debug card and local JSON contain raw/corrected angles, estimated body yaw, gyro split/predictor, residual, axis/gravity angle, separationSin, condition, observability, status/reason, timestamps and separate corrected maxima. Corrected MAX needs compensation VALID and core GOOD, using the existing stillness rules. CHECK/INVALID keep prior confirmed corrected maxima but clear the hold and withhold current corrected angle/yaw. Toggling OFF/ON starts a new experiment; new CENTER, PAUSED, SENSOR_ERROR and REFERENCE_LOST invalidate its reference and maxima.
All thresholds and bounded search limits in src/config/rearStand.ts are provisional. Display resolution is 0.1°, with full double-precision calculations; it is not a demonstrated accuracy guarantee. No accelerometer-to-position integration. [REAR_STAND_EXPERIMENT.md](REAR_STAND_EXPERIMENT.md) derives rotation order, numerical conditioning and limits. [DEVICE_TEST_PROTOCOL.md](DEVICE_TEST_PROTOCOL.md) describes the required vehicle comparison.
